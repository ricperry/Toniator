# Toniator 0.4.7 — Fast preview and native workflow

2026-11-18

Toniator 0.4.7 adds optional approximate GPU preview, native interface and keyboard
improvements, and bounded CPU responsiveness work. Linux x86_64 AppImage and
Flatpak packages include the graphical app and headless CLI. `SHA256SUMS` and
`build-info.json` identify the release artifacts and source checkpoint.
This remains a prerelease.

## Accurate and Fast preview

The **Fast preview** switch follows Zoom/Fit. Every window starts with Accurate
CPU rendering. Switch Fast on to request Vulkan rendering of supported circular
marks in RGB or CMYK; unsupported content, devices, sizes and zooms use whole-scene
CPU fallback. **Source color + alpha** retains Accurate rendering. The adjacent
readout identifies accepted pixels as Accurate, Fast or Accurate · CPU fallback;
it keeps the previous frame's identity while replacement pixels are pending.

Fast consumes the same canonical geometry, density and calibration as Accurate,
through a scene-only evaluation path. It is approximate: coverage, alpha and color
can differ, and it has no Accurate error certificate. Use Accurate to judge final
detail. Switching preserves zoom/pan, adds no undo entry or unsaved change, and
stores no preference in projects, Document Presets or application settings. Fast
does not refine automatically to Accurate while idle. PNG/SVG, print preparation,
temporal exports, gallery thumbnails and Wizard previews retain CPU rendering.

The implementation uses pinned Vello/wgpu dependencies with lazy Vulkan
initialization. Vulkan support is optional at runtime; Accurate remains available.
[Build instructions](../BUILDING.md) also describe a CPU-only application build.
The [development measurements](../PERFORMANCE.md#2026-11-02-development-fast--accurate-preview)
record specific gains for conditioned cache misses alongside competitive ordinary
CPU caching, startup and mode-cycle costs, approximation differences and resource
limits. Those measurements are not benchmarks of these release packages or a
universal speedup claim. The combined preview payload target remains a soft
8 GiB, including GPU reservation; it is not a process-memory or VRAM guarantee.

## Native workflow and keyboard access

The header groups New, Open, Save, Undo and Redo, with Settings and Main Menu on
the right. Main Menu groups File, Edit, View, Tools and Help. Native symbolic
icons, theme colors, focus indicators and dialog controls retain GTK semantics.
Local Help and Keyboard Shortcuts describe the workflow without opening external
pages unless a link is activated.

F10 opens Main Menu, Ctrl+, toggles Settings, and F6 cycles Canvas and Settings.
With Canvas focused, arrow keys pan zoomed artwork. Ctrl+0 fits, Ctrl++/Ctrl+-
zoom, F1 opens local Help, and Ctrl+? opens Keyboard Shortcuts. Text fields keep
their own text editing and history. See [interface conventions](../INTERFACE_CONVENTIONS.md)
and [accessibility support and limits](../ACCESSIBILITY.md).

## CPU responsiveness

Personal Pattern thumbnail preparation and evaluation run on one bounded worker,
keeping canonical work off GTK and rejecting stale results. Exact operation-local
mapped sampling, streamed serial Lloyd cells and earlier release of temporary
raster geometry reduce selected CPU work and memory without changing authored
density or canonical construction. Fine-resolution latency and memory remain
open followups. The [scoped development results](../PERFORMANCE.md#2026-10-31-personal-gallery-and-dense-pattern-previews)
retain their workload, producer and acceptance limits; they are not package-wide
performance guarantees.

## Formats and installation

Project and Preset formats are unchanged from 0.4.6: `.toniator` schema **19** in
container **2**, standalone Pattern format **10**, and source-free Document Preset
envelope **3** with configuration schema **18**. Ordinary projects remain
current-only. The README gallery and editor screenshots retain their original
**0.4.5** provenance; their older projects require that release. Open their source
artwork in 0.4.7 to create a current project. Supported older source-free Document
Presets retain deterministic conversion preserving original bytes and active
intent. See [format details](../USING_TONIATOR.md#046-project-and-preset-formats).

Application ID remains `io.github.ricperry.Toniator`; GitHub distribution is not a
Flathub listing. New Vello/wgpu dependency notices and pinned provenance accompany
both Linux payloads beside the existing decoder and media notices. A current
Windows package requires its own native build and verification from the exact
release source; historical Windows packages must not be relabeled.

## Remaining limits

Fast eligibility and GPU resource limits depend on scene, target, driver and
hardware. Source color + alpha SVG can still differ from native output for local
colored overlap; Spectrum SVG can conservatively refuse contour precision.
External SVG engines and fonts can differ. Dense CPU workloads and cancellation
gaps remain tracked in [known issues](../../ISSUES.md).

Development verification includes focused tests, both immutable PNG/SVG source
inputs, native output inspection, private GTK semantic/action/readback and
screenshot checks, default and CPU-only builds, and an offline GNOME SDK build.
Automated Sway/AT-SPI evidence does not establish exhaustive GNOME/Mutter,
production-portal, screen-reader-user, other-hardware or physical-print acceptance.
