# Toniator 0.4.0 — Optional garment PNG preparation

Toniator 0.4.0 is a Linux x86_64 prerelease distributed as an AppImage and a
Flatpak. The separate Windows development ZIP still contains version 0.3.2
debug binaries; this release does not include a Windows 0.4.0 package or claim
that the new features were verified on Windows.

## What changed

- PNG export options include **Prepare for garment printing**, off by default.
  Set maximum physical width and height in millimetres or inches and choose
  DPI; Toniator calculates one aspect-preserving pixel size and records the
  corresponding PNG density. The ordinary PNG path is unchanged when
  preparation is off.
- Prepared output makes pixels with alpha at least 128 fully opaque and pixels
  below 128 fully transparent. Optional export-local corrections can
  remove isolated features below a cutoff, thicken narrow positive features,
  and treat narrow gaps by averaging surrounding edges, filling with the
  selected background or custom color, or growing the gap to a minimum width.
  Each correction has an independent threshold; zero disables that correction.
- The preparation preview uses the same settings and pixels as export. It
  renders automatically when opened and after valid settings change, cancels
  obsolete work, and keeps the latest request. Settings and preview sit side by
  side with a draggable divider, zoom, and pan. Separate background and
  custom-color swatches are available; both offer **Use garment color**, which
  copies the current viewer swatch once. Preparation settings do not change or
  persist to the project.
- The headless `toniator preflight` command reports advisory measurements for
  the final transparent output. It remains separate from the prepared PNG
  workflow and does not certify print safety.
- The main artwork can be panned by dragging with the primary mouse button
  after zooming beyond Fit.

## Project compatibility and limits

Version 0.4.0 writes project document schema 11 in media container 2 and reads
schema 10 with default print-preparation settings. Saving a schema 10 project
writes schema 11; the pre-G1a v0.3.3 application cannot read schema 11. There is
no automatic downgrade. Document Presets remain format 3 with configuration
schema 10, and Pattern format remains 5.

The preparation option changes only the exported PNG when enabled. It does not
select a supplier product or placement, set a universal print threshold, or
predict fabric color, adhesion, hand, wash life, or final print quality. Width
measurements use square-grid axis conventions, so diagonal feature widths are
approximate. Resource limits can reject an export without writing a partial
file. Use supplier-specific file guidance and inspect a physical sample when
the printing process requires it; neither preflight nor preparation is print
certification.

Automated interface evidence uses a private Sway/wlroots session. It does not
establish exhaustive GNOME Shell/Mutter behavior, production file-portal
behavior, or human review. The Flatpak is distributed on GitHub and is not a
Flathub listing. Fine full-size Pattern previews and first-use personal Pattern
thumbnails can be slow; other reports and deferred work remain listed in
[known issues](https://github.com/ricperry/Toniator/blob/v0.4.0/ISSUES.md).
