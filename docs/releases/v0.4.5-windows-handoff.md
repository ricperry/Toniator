# Windows handoff for Toniator 0.4.5

Build the **same source as the Linux release**, exactly tag `v0.4.5`. This tracked
handoff survives a Git pull; ignored local planning files are not required.
Windows building and packaging remain later work. Linux verification is not
native Windows or clean-machine acceptance.

## Identify the source

Use a clean, separate native Windows checkout to preserve personal work. From
PowerShell at its repository root:

```powershell
git fetch origin main --tags
git switch --detach v0.4.5
$releaseCommit = (git rev-list -n 1 v0.4.5).Trim()
if ((git rev-parse HEAD).Trim() -ne $releaseCommit) { throw 'Wrong source checkout' }
if (git status --porcelain) { throw 'Release checkout must be clean' }
gh release download v0.4.5 --pattern build-info.json --dir target/validation/windows-0.4.5/linux-provenance
$linuxInfo = Get-Content target/validation/windows-0.4.5/linux-provenance/build-info.json -Raw | ConvertFrom-Json
$linuxInfo | Format-List
```

Compare the downloaded provenance's `base_commit` with `$releaseCommit`, and
its `version` with `0.4.5`, before building:

```powershell
if ($linuxInfo.base_commit -ne $releaseCommit -or $linuxInfo.version -ne '0.4.5') { throw 'Linux source provenance mismatch' }
```

Record the full peeled commit in Windows provenance; do not insert a guessed future hash into this document.
Keep tag `v0.4.5` fixed. Never relabel or attach the historical 0.3.2 debug ZIP.

## Native release build

Follow [native Windows prerequisites and SDK setup](../windows-build.md) with
MSVC, the pinned Rust toolchain and GTK SDK. CPU computation is portable; no
compute GPU backend or GPU-specific setup is required. Inspect the actual
scripts before using them: `build.ps1` has **no parameters** and builds debug;
`package.ps1` takes `OutputRoot`, `ExpectedAppSha256`, `ExpectedCliSha256` and
`CheckpointCommit`, but hardcodes 0.3.2 debug paths/names/metadata;
`package-verify.ps1` takes only `OutputRoot` and hardcodes that old ZIP.
They do not accept `-Release` or a version argument and cannot package 0.4.5
release binaries as-is.

The environment helper supports a direct native release build without modifying
tracked scripts:

```powershell
$ErrorActionPreference = 'Stop'
. ./scripts/windows/windows-env.ps1
$build = Initialize-ToniatorWindowsBuildEnvironment
$paths = $build.Paths
$buildExit = Invoke-ToniatorProcess -FilePath $paths.Cargo -Arguments @('build', '--release', '--locked', '--target', $paths.Target, '-p', 'toniator-app', '-p', 'toniator-cli') -Environment $build.Environment -WorkingDirectory $paths.RepositoryRoot
if ($buildExit -ne 0) { throw "Native release build failed: $buildExit" }
$releaseBin = Join-Path $paths.ProductBuildRoot ($paths.Target + '\release')
$cli = Join-Path $releaseBin 'toniator.exe'
$app = Join-Path $releaseBin 'toniator-app.exe'
$version = Invoke-ToniatorCapturedProcess -FilePath $cli -Arguments '--version' -Environment $build.Environment -WorkingDirectory $paths.RepositoryRoot
if ($version.ExitCode -ne 0 -or $version.StdOut.Trim() -ne 'toniator 0.4.5') { throw 'Wrong CLI version' }
Get-FileHash -Algorithm SHA256 -LiteralPath $cli, $app
```

The helper's `AppExecutable`/`CliExecutable` fields still point at debug outputs;
use `$releaseBin` above. Do not call the historical packager with new expected
hashes and assume its debug paths become release paths.

## Package and verify before uploading

Create new versioned portable release assets in fresh staging, for example
`Toniator-0.4.5-windows-x64.zip` and
`Toniator-0.4.5-windows-x64-sources.zip`. Packaging automation requires separately
recorded, bounded tooling work because the checked-in packager is historical. A packaging recipe can be adapted later
while preserving the exact tagged product source and recording recipe provenance.
If a product-source fix is required, stop for an explicit new checkpoint/version
decision; do not modify or move the published tag. Merely changing the ZIP name
is insufficient.

Bundle the full GTK/runtime closure, launchers, schemas, icons, source and license
notices, vendored iOverlay/i_tree provenance and JPEG XL notices. Verify the
payload notices against the current dependency closure rather than copying a
stale debug inventory. Document media bundling or optional setup truthfully.
Retain original source archives and build recipes as required by their licenses.

Smoke-test the extracted release package from a path containing spaces and
Unicode, with an isolated PATH and personal data. Check CLI version/help and
real PNG/SVG renders from both immutable baseline artworks; inspect native RGB
and alpha without flattening. Exercise GUI launch, Open, edit, save/reopen,
PNG/SVG export, JPEG XL still/animation and cancellation. Check runtime dependency
closure and launcher behavior on native Windows; record clean-machine coverage,
unsigned status, media availability and any remaining limits. Cross-compilation
or Linux private-Sway results cannot replace these checks.

Write `Windows-build-info.json` with version `0.4.5`, exact source commit,
release profile, native OS/compiler/Rust/GTK identities, binary and asset hashes,
notices inventory and actual smoke-test results. Write `WINDOWS-SHA256SUMS` for
the distinct Windows ZIPs and provenance file; verify freshly extracted assets.
The Linux `build-info.json` and `SHA256SUMS` must remain unchanged.

## Append to the existing release

After native packaging and verification pass and upload is authorized:

```powershell
gh release view v0.4.5 --json tagName,isDraft,isPrerelease,assets
gh release upload v0.4.5 dist/Toniator-0.4.5-windows-x64.zip dist/Toniator-0.4.5-windows-x64-sources.zip dist/WINDOWS-SHA256SUMS dist/Windows-build-info.json
```

Use no `--clobber`. If any Windows asset name already exists, stop and inspect it.
Do not create a second release, replace Linux assets, change prerelease status,
or move the tag. Download the new assets into a fresh directory and verify their
checksums and exact-tag provenance. Update release notes truthfully only after
Windows assets exist and pass native checks; retain historical 0.3.2 identifiers.
