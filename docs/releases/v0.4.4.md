# Toniator 0.4.4 — Shared CPU performance and GUI refinements

2026-10-16

Toniator 0.4.4 combines the main-window refinements from GUI checkpoint
`8ee739375313e11c07a325f297a9e91a257ac963` with measured improvements to shared
preview, accepted-scene reuse and Random/Dispersion computation. The Linux
x86_64 prerelease provides AppImage and Flatpak packages with the GUI and CLI.

## Workflow and performance

The Settings inspector uses a preferred width that follows text size, with a
full-width Settings view on narrow windows and a pinned **Back to canvas**
action. Related settings use progressive disclosure, long dialogs scroll above
their actions, and passive memory readouts live in Advanced Settings Diagnostics.
The fixed welcome window keeps Recent Files within a bounded scrolling area.

Three CPU changes work beneath Pattern configurations: a checked one-pass
clipped raster union, exact accepted-scene reuse through `SceneReuseGuard`, and
shared Random/Dispersion ordinal storage with an automatically selected dense
cell table. Dense metadata is bounded at 16 MiB; ineligible layouts and failed
dense reservation use checked sparse storage. This storage bound does not limit
creative density. Streaming fingerprints retain the same FNV bytes and ordering.
Numerical predicates, seeded arrangements, canonical geometry and output quality
remain unchanged. No new dependency, GPU backend, driver setup or user setting
is introduced; ordinary CPU execution remains available.

Measured on the development host with the immutable PNG/SVG source artworks:

| Measured workload | PNG source | SVG source |
| --- | ---: | ---: |
| P1 fine engine preview | 33.3% lower time | 38.7% lower time |
| P2 warm accepted Maze request | 29.0× faster | 30.3× faster |
| P3 fine Even family generation | 2.54× faster | 2.25× faster |
| P3 fine Even complete engine API | 19.8% lower time | 15.4% lower time |
| P3 fine Even private GTK ticket acceptance | 19.5% lower time | 18.2% lower time |

These compare separate staged baselines and are **not additive** or universal
speedups. Tracked family allocation calls fall more than 99.9%; requested peak
capacity falls about 12–17% for fine Even and 37% for fine Clustered. These
windows exclude allocator metadata, decode and other process costs. Total SVG
process peak RSS rises 1.46%, so memory reduction is workload-specific.
See [measurements, exactness, limits and reproduction](../PERFORMANCE.md) and
[current source-free performance Presets](../../fixtures/performance/README.md).
Existing iOverlay checked operations are reused under MIT OR Apache-2.0;
[credits and provenance](../PERFORMANCE.md#credits) remain available.

## Retained capabilities and limits

Native JPEG XL still/animation and image-sequence source support from
[0.4.3](v0.4.3.md) is retained, including original encoded project bytes and
bundled decoder dependency notices. Project schema 17 in media container 2,
Document Preset format 3/configuration schema 16, and Pattern format 8 are
unchanged. Ordinary projects remain current-only; supported older source-free
Document Presets retain deterministic conversion and original bytes.

Calibration, checked native/unclipped union, weighted topology/refinement and
large connected/curve SVG serialization remain expensive. Some large SVG cases
reach bounded timeouts; early SVG decode still delays cancellation. Exactness
and cancellation checks do not establish completion of those timed-out exports.
Scoped tests, strict affected-target Clippy, release builds, native output review
and private GTK checks cover the implementation. Sway/wlroots results do not
establish GNOME/Mutter, production portals, human or physical-print acceptance.

Linux packages use `io.github.ricperry.Toniator`; attachments include
`SHA256SUMS` and `build-info.json`. This is a GitHub prerelease, not a Flathub
listing. Broad distribution compatibility remains unestablished. The separate
Windows development package remains 0.3.2; this publication does not provide a
0.4.4 Windows package. The tracked [Windows handoff](v0.4.4-windows-handoff.md)
describes a later native build from this exact release tag and safe asset append.
See the [packaging guide](../../packaging/README.md) and
[known issues](../../ISSUES.md).
