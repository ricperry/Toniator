# Toniator 0.4.5 — Preview recovery, curve capacity and smaller SVGs

2026-10-18

Toniator 0.4.5 adds shared preview recovery, removes obsolete capacity ceilings
from the measured round/square spiral route, and fixes excessive SVG nodes on
nearly straight curve sections. The accepted replacement adds checked intersection
capacity, cause-specific Details and automatic local failure logs, together with
an expanded README and reproducible examples. It retains version **0.4.5**.
This replaces the earlier 0.4.5 build while retaining its changes and limits.
Linux x86_64 AppImage and Flatpak packages include the graphical app and headless
CLI. Release attachments record their exact source checkpoint and checksums.
This remains a prerelease.

## Preview recovery

A failed preview stops repeating source preparation and rendering for the same
state. **Preview unavailable** appears over the canvas while the last successful
preview stays visible; a first failure says **No preview yet**. **Retry preview**
makes one new attempt. **Dismiss preview error** hides the message without
restarting work. The status tooltip and accessible description retain the full
diagnostic. Editing the artwork settings, changing the frame or view, or opening
a different workspace can request a new preview normally.

Preview failures preserve independent operation and Save errors. Canceled and
stale requests cannot replace accepted pixels or publish partial cached output.
The overlay's actions remain reachable through focus scrolling in narrow windows
and large text without changing the preview's raster target. The existing main
window minimum width can still clip header/status content on a 480 px output.

## Accepted replacement: intersection capacity and diagnostics

Two naturally reproduced non-memory failures are corrected: a valid 513-segment
authored path with one crossing exceeded the former 262,144 candidate-pair
ceiling, and 10,000 isolated contacts exceeded the former 4,096-result ceiling.
Normal intersection work now uses checked counts, fallible storage and
cancellation. Existing predicates, tolerances, subdivision depth, stable contact
order and explicit finite caller policies remain authoritative. No automatic
simplification, precision reduction or recalibration is introduced. Both immutable
source types pass compatible color-mode checks; 14 successful small control
artifacts and six original native artifacts remain exact. These are bounded
regression checks, not exhaustive proof for every valid recipe.

**Details…** is available for main, Pattern Wizard, Pattern Editor and Advanced
Settings preview failures. Its read-only report includes **Copy details**, copy
feedback, Close/Escape and focus restoration. Only audited actual memory reserve
failures receive memory guidance appropriate to geometry, source preparation or
preview pixels. Count, addressability, numerical and unknown failures remain
software errors without artwork-reduction advice. Main Retry can recreate an
unavailable worker; stopped private previews recover by closing and reopening.
Worker identity and queue/death synchronization prevent stale publication and
stranded newly queued work.

Every genuine current terminal preview failure automatically attempts a bounded
local report, regardless of cause, opening Details or an unsaved document.
Actual cancellation/supersession after edits or restarts, stale/closed work and
absent, invalid-form or unallocated intent remain quiet. Details/Copy/Dismiss
and other presentation actions never append records; a failed explicit retry
can record one new attempt.

Linux normally stores schema-1 NDJSON at
`$XDG_STATE_HOME/Toniator/preview-failures.log`, falling back to
`$HOME/.local/state/Toniator/preview-failures.log`. The primary is bounded to
2 MiB with two backups, entries to 32 KiB and serialized context to 8 KiB.
New Unix files use mode `0600`; nonregular and symlink destinations are rejected.
Writes are best effort and failures are nonfatal. Captured metadata excludes
source pixels/bytes/hashes, project names/paths and full recipes; raw producer
messages can contain local paths, so review reports before sharing. No telemetry
is added. OS OOM kills or allocator aborts may terminate before any record exists.

Coverage includes requested startup/bridge failures, main/private previews,
active Print/PNG failures and positive checked viewport refusals. Existing
preview guards remain unchanged: the natural 8193×8192 Print refusal exercises
its 256 MiB retained-preview guard and is a software capacity refusal, not OOM.
GTK fault injection verifies routing and recovery, without claiming natural OOM.
A real unsaved revision logs a current injected failure and retries without
saving. Huge main-viewport refusal has source/unit evidence only. See
[Preview recovery and local diagnostics](../PREVIEW_DIAGNOSTICS.md).

## Dense curves and editable SVG

Dense round and square spirals can grow beyond their former 4,096-segment
construction limit and fixed path/clipping count ceilings. Checked counts,
fallible incremental storage, cancellation and explicit finite caller limits
remain authoritative. Machine addressability does not guarantee available RAM;
unrelated family and numerical policies remain in place.

SVG export now subdivides curves for curvature accuracy rather than chord span
alone, retaining its existing 1e-8 canvas-relative accuracy target, fill rules,
paint order, clipping and editable geometry. The reported square-crossing example
shrinks from **56,493,266 to 473,528 bytes** (about 119×), with line commands reduced
from **1,550,716 to 12,806**. Canonical geometry, identities, raw f64, RGBA and PNG
remain exact across all 14 baseline cases covering both immutable source types.
The eight corrected spiral SVGs intentionally change; old/new inspection checks
preserve topology with small antialiasing edge differences, not pixel identity.

Narrow numerical corrections also resolve the original document's native and
Fit-preview flattening failures. Exact chord certificates or a bounded local
winding-area charge use the existing cumulative raster error budget only at a
previous numeric failure. Existing successful branches, positional tolerance,
source geometry and normal circle accounting remain unchanged.

The unchanged 5016×5016 GoatLocker project now completes actual GTK preview and
native transparent PNG/editable SVG export. One observed preview acceptance takes
7.624788 s and remains settled for 60 seconds without unsolicited work. The app PNG
has decoded RGBA identical to headless output; its 98,454,149-byte SVG has four
editable paths, no embedded images, and matches repeated headless serialization.
The original previously failed, so this is completion evidence, not a measured
before/after speedup. Small isolated controls show no material regression within
their scoped observations. See [measurement boundaries and reproduction](../PERFORMANCE.md#045-preview-recovery-and-curve-capacity).

## Retained formats and remaining limits

Original encoded source bytes and saved calibration are retained. Project schema
17 in media container 2, Document Preset format 3/configuration schema 16, and
Pattern format 8 are unchanged. Ordinary projects remain current-only; supported
older source-free Document Presets retain deterministic conversion and original
bytes. Native JPEG XL and existing media/export capabilities remain available.
No dependency, GPU backend or new setup requirement is introduced.

Synchronous SVG Boolean processing has a measured cancellation response up to
**420.392 ms**, above the nominal 250 ms target; early source decoding retains its
known cancellation gap. No universal cancellation deadline is claimed.
External CMYK SVG rasterization can require substantial memory: native-size
resvg inspection succeeds in 49.856 s at 11,040,692 KiB peak RSS, while a bounded
native Inkscape attempt remains incomplete. librsvg 2.62 renders only cyan and
transparency for that document; the existing compositor is unchanged. These
viewer costs and compatibility limits are distinct from completed native export.

Focused tests, strict affected-target Clippy, release builds, output inspection
and private GTK checks cover the accepted work. Automated Sway/AT-SPI evidence
does not establish GNOME/Mutter, production portals, human assistive-technology
or physical-keyboard acceptance, native Windows, or physical-print safety.

Linux packages use `io.github.ricperry.Toniator`, with `SHA256SUMS` and
`build-info.json` attachments. This is a GitHub prerelease, not a Flathub listing;
broad distribution compatibility remains unestablished. The
[0.4.5 Windows handoff](v0.4.5-windows-handoff.md) describes a separate native build
from the replacement release tag and safe asset append. This Linux release makes no
0.4.5 native Windows build claim. Other historical releases and their assets
remain intact.
