# Toniator 0.4.3 — JPEG XL sources

2026-10-14

Toniator 0.4.3 adds native JPEG XL (`.jxl`) source support for still artwork,
animated artwork, and ordered sequences of still images. The Linux x86_64
prerelease targets AppImage and Flatpak, with the graphical app and headless CLI.

## What changes

- Open accepts JPEG XL artwork, with a dedicated file filter. Import image
  sequence includes JPEG XL stills and rejects animated entries.
- Saved projects retain the original encoded JPEG XL bytes for both still and
  animated sources. Animation preserves exact frame timing, variable durations,
  orientation, references, and blended frames. Embedded loop tags are ignored;
  the source is one finite pass through its displayed frames.
- Native Rust `jxl-oxide 0.12.6` with moxcms handles ICC conversion, grayscale,
  16-bit inputs, and straight alpha. No system libjxl or FFmpeg is needed for
  JPEG XL decoding. Output normalizes to Toniator's existing straight-sRGB8
  source representation; HDR and high-bit-depth output preservation are outside
  this implementation.
- Original license texts and provenance for all 18 new locked decoder
  dependencies are included in the shared package payload. See
  [dependency notices](../../THIRD_PARTY_LICENSES/jpegxl/PROVENANCE.md) and
  [media notices](../../packaging/MEDIA-NOTICES.md).

## Limits and formats

Primary associated/premultiplied alpha is explicitly rejected with a diagnostic
requesting straight alpha, including animated inputs. Import bounds include
128 MiB compressed bytes and 64 megapixels. The decoder's 512 MiB grid/cache
allocation cap does not bound total process memory; cancellation is cooperative
between native decoder operations. No performance claim is made.

Formats remain project schema 17 in media container 2, Document Preset format 3
with configuration schema 16, and standalone Pattern format 8. Projects that
embed JPEG XL sources require 0.4.3 or later; older binaries cannot open them.
Ordinary projects remain current-only. Supported older source-free Document
Presets retain their deterministic conversion path and original bytes.

## Verification and packages

Focused decoder and engine checks cover ICC, grayscale, 16-bit and fractional
alpha, orientation, variable timing, blended references, truncation, original-byte
roundtrips, sequence order, animated-entry rejection, and both immutable baseline
artworks. App/CLI checks and focused Clippy checks pass.

Private-Sway evidence verifies the native Open chooser's JPEG XL selection and
sequence chooser listing, plus animation Start/End source previews. The existing
GTK chooser hierarchy, roles, enabled state, selection/actions, and keyboard
selection remain authoritative; semantic readback, screenshots, and logs agree.
This automated evidence does not establish human, GNOME/Mutter, production-portal,
or comprehensive assistive-technology acceptance. Broad distribution compatibility
is not established.

Linux packages use `io.github.ricperry.Toniator`. The separate Windows development
package remains version 0.3.2; no 0.4.3 Windows package is provided.
Release attachments provide `SHA256SUMS` and
`build-info.json`. See the [packaging guide](../../packaging/README.md) and
[known issues](../../ISSUES.md).
