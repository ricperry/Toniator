# Toniator 0.4.6 — Artistic controls and background preview

2026-10-20

Toniator 0.4.6 adds coordinated artistic controls, placement-aware coverage and
whole-artwork background preview refinement, with bounded renderer and export
repairs. Linux x86_64 AppImage and Flatpak packages include the graphical app and
headless CLI. `SHA256SUMS` and `build-info.json` identify the exact release
artifacts and source checkpoint. This remains a prerelease.

## Artistic controls and coverage

Tone sampling follows Feature size proportionally, with a separate fineness
control. Connected geometry gains explicit connection-selection controls while
preserving complete topology and keeping geometric spacing distinct from
selection. Built-in Pattern Wizard configurations reuse valid prepared
calibration; missing active fits are prepared before Apply publishes one history
change. Existing valid calibration remains reusable without a fresh fit.

Persistent **Fixed / Cover** intent applies across Pattern families. Cover follows
canvas placement, including translation and rotation, without rewriting saved
coverage/calibration authority. Fixed retains the authored finite extent.
Certified Canvas construction can omit provably irrelevant off-canvas geometry
while preserving full sites, topology, logical work and numerical authority;
unsupported cases retain complete construction. The scoped development
[measurements](../PERFORMANCE.md#046-certified-construction) compare those two
routes for the same new recipe, not the old and new releases.

## Background preview and panning

Each visited eligible zoom fills the whole artwork in the background on fixed
1536-pixel cells. Visible regions receive priority while other visited zooms keep
progressing; panning does not cancel their work. The closest certified cached
resolution supplies coverage as requested detail streams in, and completed
regions remain reusable. After an edit at a retained zoom, a new full-image Fit
fallback supplies coverage before detail resumes at the same zoom and scroll.

Retention is automatic, for the current artwork/frame and in memory only, with
an **8 GiB soft target**. It neither reserves that amount upfront nor caps process
RSS. Older unpinned zooms can be evicted; oversized or unsupported roots use the
ordinary renderer. Preparation, certification and painting run on a dedicated
worker; GTK owns widgets and textures. Stored pixels still require current
whole-view numerical permission before display.

A thin, three-pixel native progress bar at the canvas bottom reports background
completion and hides when work finishes. Tiled GDK paintables now invalidate
dynamic contents correctly and retain disjoint full-canvas fallback coverage.
The user confirms the rebuilt cache works on their desktop without blackouts;
automated held-motion checks cover the recorded samples. Routine canvas status
hover hints are removed; progress indicators and error **Details…** remain.
See [performance boundaries](../PERFORMANCE.md#046-retained-preview-regions).

## Renderer and export repairs

Focused reproductions correct high-zoom precision accounting, raster fill-rule
handling, finite-transform and sampled-math guards, deterministic unique SVG IDs,
and RGB/CMYK SVG composition. RGB SVG uses premultiplied linear additive color;
composition references live channel groups while retaining editable geometry.
SVG publication stages output atomically so a prepublication failure or
cancellation preserves an existing destination. Temporal exports check late
cancellation and distinguish saved output from subsequent durability or cleanup
warnings. These are bounded repairs; [the renderer audit](../RENDERER_AUDIT_2026-10-20.md)
records exact evidence and remaining findings.

## Project formats and older artwork

Current `.toniator` projects use **schema 19** in **container 2**; standalone
Patterns use **format 10**. Ordinary projects are current-only. Previously
published 0.4.5 packages wrote schema 17; those projects and superseded development
schemas are rejected. Current schema 19 projects saved by the unpublished app
remain valid even when that app displayed version 0.4.5: the project schema,
not the software version label, determines compatibility. Keep the published
0.4.5 app to reopen its older projects, or open their source artwork in 0.4.6
and create a new project. No general project migration is provided.
The README's editor screenshots and 20 gallery exports retain their original
**0.4.5** attribution and project bytes.

Source-free `.toniator-preset` Document Presets are the supported conversion
exception: envelope **3**, configuration schema **18**. Supported older Presets
convert deterministically, preserving original bytes and active authored intent
for All, named channels and animation End. New defaults and genuinely prepared
replacement calibration can change appearance. Unknown profiles are rejected.
See [format and conversion details](../USING_TONIATOR.md#046-project-and-preset-formats).

## Remaining limits and verification scope

Source color + alpha SVG can still differ from native output for colored local
overlap. Spectrum editable SVG can conservatively refuse contour precision before
publication. Ordinary SVG/vector Boolean work and cancellation gaps remain;
external SVG engines, fonts and GTK/GPU interpolation can differ. The retained
cache is not an FPS, universal speedup, backend byte-parity or total-memory
guarantee. Historical development measurements retain their own source/binary
pins and are not benchmarks of the 0.4.6 packages.

Focused tests, native PNG/SVG inspection and private GTK checks exercise both
immutable project-wide source inputs. Automated Sway/AT-SPI results do not
establish exhaustive GNOME/Mutter, production-portal, human keyboard or physical
print acceptance. This Linux release makes no native Windows 0.4.6 build claim;
historical Windows packages must not be relabeled. Packages use application ID
`io.github.ricperry.Toniator`; GitHub distribution is not a Flathub listing.
