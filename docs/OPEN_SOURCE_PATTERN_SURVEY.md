# Open-source pattern techniques for Toniator

Research snapshot, 2026-11-18. This survey helps artists and developers compare useful visual additions, integration costs and candidates for a future experiment. Faithful channel tone and expressive texture receive equal weight.

## The useful additions

The strongest small experiments are a **progressive blue-noise ranked screen** for fine, evenly dispersed grain and **level-interleaved vector hatching** for engraved or plotted shading. Population-adaptive LBG stippling remains a more expensive texture and distribution-quality challenger that must earn a rerun against existing pilot evidence. Adaptive motif selection offers another distinctive direction once tone and shape identity are settled.

The [current tracker](../ProgressTracker.md) already records Random, Poisson disk, Jittered cells and Clustered alongside Bayer 8×8, Floyd–Steinberg, Ink-weighted quadtree, Tangent ribbons and Stochastic cluster screen. Tangent ribbons has Spacing, Size and Blend. Shape Library already supplies custom marks. Another dot icon or diffusion kernel needs a visible benefit beyond this baseline. The older [TON-010 proposal](TON010_STIPPLING_RESEARCH_PLAN.md) remains useful research context, with its four-generator inventory superseded by the current development checkout.

## What PhotoCraft’s speed can teach Toniator

PhotoCraft’s built-in Color Halftone renders pixels in parallel tiles on native CPUs. Many pixels touch the same screen dot. PhotoCraft samples the source ink at five points and caches the resulting radius once per rotated cell and channel within a tile. On its 16-vCPU benchmark, this brought a 24-megapixel RGB filter application from 1,137 ms to 604 ms with identical output. The timer ends before window presentation. Toniator already builds reusable geometry. A profile can show whether repeated evaluations still sample the same logical cell for the same channel and settings. Sharing those results would be worth measuring from edit to presented frame. ## Ranked screens and dependent raster methods

**1. MomentsInGraphics BlueNoise.** Christoph Peters supplies actual [CC0 textures, tonal examples and spectral analysis](https://momentsingraphics.de/BlueNoise.html), with [void-and-cluster generation code](https://github.com/MomentsInGraphics/BlueNoise/blob/master/BlueNoise.py). The generator assigns every lattice location a unique integer rank. Increasing tone reveals nested subsets, giving fine stipple grain with less Bayer weave and less clustered mottling. Offline generation plus runtime threshold lookup is a modest integration candidate. Preserve full integer ranks when exact nesting/count control matters. An 8-bit image can repeat thresholds. Tile repetition, lattice visibility and finite mark footprints remain visible-quality questions.

A low-cost architectural hook follows the current independent-screen route. Map each global logical cell index to a ranked threshold, compare it with the sampled channel value, then emit an existing Shape Library mark in stable cell order. The shared canonical scene supplies both preview and SVG. Global indices preserve phase across tiles and off-canvas guards. The new work is ranked-screen lookup and geometry coverage calibration.

**2. libplacebo.** Its [lookup generator](https://github.com/haasn/libplacebo/blob/f2e04cb1840ef1f1586b71050bff40b04cbd8d91/src/dither.c) constructs a low-energy dither matrix using a different procedure. Its [GPU diffusion implementation](https://github.com/haasn/libplacebo/blob/f2e04cb1840ef1f1586b71050bff40b04cbd8d91/src/shaders/dithering.c) preserves dependencies using shifted columns, workgroup barriers and shared memory. This is valuable engineering evidence that diffusion can run on GPU, with image-height memory and scheduling constraints. The [official options](https://libplacebo.org/options/#error_diffusion) discourage its use in time-critical rendering. LGPL-2.1-or-later code is a reference for a bounded port. Importing a video renderer would add considerable unrelated machinery.

**3. libdither.** [Tone-dependent Ostromoukhov weights](https://github.com/robertkist/libdither/blob/7bf49c5324b8b8d5ce321d549f89fb6c75a9d859/src/libdither/dither_varerrdiff.c) can alter worms and directional grain beyond Toniator’s fixed Floyd kernel. [Dot diffusion](https://github.com/robertkist/libdither/blob/7bf49c5324b8b8d5ce321d549f89fb6c75a9d859/src/libdither/dither_dotdiff.c) uses ranked classes with block-boundary risks. [Direct binary search](https://github.com/robertkist/libdither/blob/7bf49c5324b8b8d5ce321d549f89fb6c75a9d859/src/libdither/dither_dbs.c) repeatedly toggles/swaps pixels to improve filtered error, making a useful offline quality comparator. Diffusion retains causal order, and DBS has repeated search cost. The Zhou–Fang branch also needs deterministic RNG replacement. Its [custom permissive license](https://github.com/robertkist/libdither/blob/7bf49c5324b8b8d5ce321d549f89fb6c75a9d859/LICENSE) and additional notices require file-level review.

**4. Ghostscript’s CalComp screen.** The [167×167 stochastic threshold asset](https://github.com/ArtifexSoftware/ghostpdl/blob/74b866a61d757d0014f7070623a594b86bbed68d/lib/ht_ccsto.ps) is explicitly public domain. Its examples decorrelate color separations. It offers a genuine print-oriented screen comparator at low integration effort, although byte thresholds have ties and periodic reuse can become apparent. That asset’s permission is separate from the Ghostscript engine’s AGPL/commercial licensing. Treat channel decorrelation as an experiment requiring union/overlap checks.

These methods decide raster occupancy. A Toniator adaptation must explicitly emit canonical sites, marks or regions and calibrate that geometry. Substituting circles for occupied squares changes diagonal contacts, coverage and holes.

## Growing marks, holes and vector strokes

**5. GEGL Newsprint.** The [LGPL-3.0-or-later implementation](https://github.com/GNOME/gegl/blob/838e2ce9c5624f4a5af9eb6c88482184147000e0/operations/common/newsprint.c) contains Euclidean dot growth through diamond forms into corner holes, with channel period/angle controls. The aesthetic addition is a recognizably printed transition from isolated ink dots to joined dark regions with small clear holes. Canonical contour construction and calibrated topology changes make this a medium-to-high effort candidate. Independently scaling Shape Library outlines does not establish the same growth law.

**6. Krita Screentone.** [Actual GPL-2.0-or-later spot functions](https://github.com/KDE/krita/blob/afc124763282f5387735760cdda838c1c81545a1/plugins/generators/screentone/KisScreentoneScreentoneFunctions.cpp) include waves and curtain patterns. Its [illustrated manual](https://docs.krita.org/en/reference_manual/layers_and_masks/fill_layer_generators/screentone.html) explains function/template equalization that connects threshold to covered area. Sine waves could give fabric-like rhythm, while curtains give folded bands. Toniator would need global phase, shared geometry and a measured area response. Equalizing a raster template alone does not validate vector coverage. This is a strong reference for both appearance and predictable tone controls.

**7. plottertools/hatched.** Its [MIT `_build_hatch` implementation](https://github.com/plottertools/hatched/blob/f31db1f713ddec820641e677646fc3c568446997/hatched/hatched.py#L184-L268) extracts grayscale contours and clips interleaved offset lines or circular rings at multiple tonal levels. The [upstream examples](https://github.com/plottertools/hatched) show the actual plotted result. Increasing darkness adds strokes in stages, producing engraved shading or concentric topographic texture. This adds a distinct mechanism beyond tangent-guided point rows. Existing canonical paths make it promising, with medium effort for contour extraction, clipping, stroke footprints and tonal-level transitions. Contour work and path counts remain costs even when individual clipping operations parallelize.

**8. Chafa.** Its [LGPL-3.0-or-later symbol selector](https://github.com/hpjansson/chafa/blob/6c19a0fa476cd49530dffe96814732d3e86a3047/chafa/chafa-symbol-map.c#L1189-L1264) shortlists candidates using 64-bit subcell bitmap Hamming distance. The [input/output examples and gallery](https://hpjansson.org/chafa/) show how motif choice preserves recognizable structure. For Toniator, comparable-ink arcs, wedges or tiny strokes could respond to local structure while retaining grain. Store canonical paths with stable shape IDs. Font/glyph dependencies would make saved artwork and SVG less predictable. This needs motif matching and coverage calibration beyond today’s freely chosen custom mark, and could remain optional symbolic detail.

## Continuous stippling and controlled populations

**9. StippleGen.** The [LGPL-2.1-or-later Processing implementation](https://github.com/evil-mad/stipplegen/blob/ef2e3ca3c52af298e9e63b3c3d8f9a3414d18656/StippleGen/StippleGen.pde) demonstrates weighted Lloyd relaxation, adjustable dot sizes and SVG output. Its 500-cell calculation batches illustrate cooperative responsiveness. The artistic result is familiar carefully spaced illustration. Existing weighted Lloyd already covers much of this territory, so incremental product value is limited. Its strongest role is a concrete baseline for source integration, continuous sites and vector output.

**10. Single-class LBG stippling.** The [LGPL-3.0 demo solver](https://github.com/MarcSpicker/LindeBuzoGrayStippling/blob/a056b91bec8a7af4c7bf1df3d749651d7b59bce3/src/lbgstippling.cpp) compares integrated cell ink with mark footprint, then removes, moves or splits sites with hysteresis. Population adaptation gives control beyond relaxing an already fixed population. The [existing Toniator pilot](../target/validation/ton010-pilot-20261118/report.md) already tested a Cell split and merge candidate. At seed 1, mean absolute ink errors in 32-pixel windows were 8.4/8.9 percentage points on raster/vector samples, against 3.5/4.1 for the current Poisson disk with Variable marks. That control was more faithful on both samples. This does not establish parity with the upstream LBG solver, but a rerun needs a specific improvement hypothesis. Cell integration, repeated diagrams, stable births/deaths and cancellation make integration substantial. The demo uses OpenGL cone diagrams and CPU reduction. Its [authors explicitly distinguish it](https://github.com/MarcSpicker/LindeBuzoGrayStippling#disclaimer) from the code behind paper timings and images. Those timings cannot predict Toniator responsiveness.

**11. cyCodeBase weighted sample elimination.** The [MIT implementation](https://github.com/cemyuksel/cyCodeBase/blob/62da186e0b2f2d3673d1f18386c66caf5798cd9b/cySampleElim.h) greedily removes conflicting surplus candidates using spatial search and a heap. Its [progressive examples](https://www.cemyuksel.com/research/sampleelimination/) demonstrate useful nested subsets. It suits an exact dot budget and predictable progressive reveal. Source-adaptive candidate generation and tone calibration remain Toniator work. Serial elimination, oversampling memory and C++ integration add cost. It creates no missing sites and gives no maximal-coverage guarantee. Defer unless exact counts or continuous progressive populations become a concrete requirement.

## Color reduction and coordinated layers

**12. libimagequant.** This Rust library performs real palette selection with [median-cut and k-means refinement](https://github.com/ImageOptim/libimagequant/blob/9388d26902c53854c4f666dc3f07db6504b16924/src/quant.rs), then [adaptive Floyd remapping](https://github.com/ImageOptim/libimagequant/blob/9388d26902c53854c4f666dc3f07db6504b16924/src/remap.rs). It can make a limited-palette illustration with stable flat colors and controlled noise. Its [API and GPL-3.0-or-later/commercial terms](https://pngquant.org/lib/) are clear. Palette selection and color-distance choices would be new product semantics. Per-channel RGB/CMYK halftoning instead controls coverage of existing paints. A palette image does not define printable separations or canonical vector regions. Defer integration until an artist actually needs palette reduction.

**13. MLBGStippling.** The [MIT CUDA/Thrust implementation](https://github.com/UniStuttgart-VISUS/MLBGStippling/blob/9fcc5d894c11a8b8d29f716de0dabc533293ff16/libstipple/src/stippler.cu) couples per-class and global optimization. Its [examples and unmixing workflow](https://github.com/UniStuttgart-VISUS/MLBGStippling) address colored and inverted stippling. Coordinating layers could improve combined grain and overlap while preserving individual tone. This changes inter-channel optimization semantics and requires an AMD-portable solver with CPU fallback. High effort and experimental options make it a later research reference.

## A fair experiment

Begin any separately authorized comparison with the ranked blue-noise screen and level-interleaved hatch. Compare the former with Bayer, Poisson and clustered screens, and the latter with Tangent ribbons at matched visible tone and feature scale. Retain the pilot’s calibrated Variable Poisson control. A continuous-dot LBG rerun should identify how its solver or calibration addresses the measured split-and-merge deficit. These are recommendations, with no new prototype timing claims.

| Priority | Candidate and reason |
| --- | --- |
| First trials | Ranked blue-noise screening and interleaved hatching offer different visible outcomes through bounded geometry work. |
| Next | Adaptive motif selection and calibrated spot-function growth add expressive shape behavior. LBG needs a concrete case for improved texture or distribution quality. |
| Hold | Further diffusion variants, DBS, elimination, palette reduction and MLBG await a specific need that justifies their additional contracts or cost. |

Before overlap, expected coverage is approximately **site density × mean mark area**. Spacing changes population, Size changes area, and a mix needs an explicit allocation of each. Measure the actual rendered union, including holes, alpha, clipping and curved-mark overlap. Preserve global phase and off-canvas guards before final clipping. Minimum printable dot and hole sizes need a named process and physical evidence.

Use both immutable artworks in [assets/README.md](../assets/README.md), plus ramps, flat tones, edges and light/dark detail. Match seeds, channel mappings and coverage. Inspect native RGBA and SVG, local tone error and texture spectra/FFT. Check worker-count, CPU/GPU and tile/full-canvas parity, cancellation and deterministic replay. Measure slider input to first correct presented frame and complete canonical geometry, including sampling, transfers, compaction, paths, memory and export. Current [performance evidence](PERFORMANCE.md) already preserves ordered CPU decisions while accelerating eligible independent work. A parallelizable kernel establishes no end-to-end speedup.
